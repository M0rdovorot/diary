# Voice Bot — контекст проекта

## Что это
Личный Telegram-бот на Go: принимает голосовые сообщения, распознаёт речь локальной моделью, делает структурированное саммари через локальную LLM. Всё self-hosted — приватность в приоритете, внешние API (OpenAI и т.п.) не используются принципиально.

## Нагрузка
Один пользователь, ~20 минут голосовых в день суммарно, разово в день. Реал-тайм обработка не нужна — задержка в пределах нескольких минут допустима.

## Сервер
- Провайдер: Timeweb Cloud, тариф **Cloud MSK 50**
- Характеристики: 4 x 3.3 ГГц CPU, 8 ГБ RAM, 80 ГБ NVMe
- ОС: Ubuntu 26.04
- **Важное ограничение:** 8 ГБ RAM впритык для одновременной работы Whisper + LLM. Планируется своп-файл 4 ГБ как буфер. Нужно следить за потреблением через `docker stats` / `htop`.

## Стек
- **Backend:** Go, Telegram-бот через long polling (например, `go-telegram-bot-api`) — без вебхука, чтобы не нужен был домен/SSL на старте.
- **STT (речь → текст):** faster-whisper через Docker-образ `onerahmet/openai-whisper-asr-webservice`. Модель `small`, квантование int8. При нехватке памяти — понизить до `base`.
- **LLM (саммаризация):** Ollama, модель `qwen2.5:3b-instruct-q4_K_M`. Намеренно взята маленькая модель — 7B рискованно гонять одновременно с Whisper на 8 ГБ RAM.
- **Postgres и Redis:** НЕ используются на старте. Добавятся позже — Postgres для истории транскриптов/саммари, Redis как очередь задач или кэш. Ресурсы сервера (CPU/RAM) можно поднять через панель Timeweb без пересоздания сервера.
- Всё разворачивается в Docker / Docker Compose.

## Приватность (почему всё именно так)
Ключевое требование пользователя — данные (голос, расшифровки) не должны уходить к сторонним сервисам. Поэтому выбор пал на локальные модели (faster-whisper, Ollama) вместо облачных API типа OpenAI Whisper/GPT.

## План по шагам

1. **[Черновик готов, на сервере ещё не выполнено]** Базовая настройка сервера: non-root пользователь, вход по SSH-ключу, UFW firewall, fail2ban, установка Docker Engine + Compose, своп-файл. Скрипт: `01-setup-server.sh` (был подготовлен ранее в чате — при необходимости пересоздать).
2. **[Черновик готов, на сервере ещё не выполнено]** `docker-compose.yml` с сервисами `whisper` и `ollama` (сервис `bot` пока закомментирован). Файлы: `docker-compose.yml`, `.env.example`.
3. **[Следующий шаг]** Написать Go-бота: long polling, обработчик voice-сообщений (получение `file_id` → скачивание OGG-файла во временную директорию).
4. Подключить бота к Whisper по внутреннему docker-адресу (`WHISPER_URL` из `.env`), получать текст расшифровки.
5. Подключить бота к Ollama (`OLLAMA_URL`, `OLLAMA_MODEL` из `.env`), задать system-prompt со структурой саммари. **Структура саммари ещё не определена пользователем — уточнить перед этим шагом.**
6. Собрать пайплайн целиком: voice → download → whisper → llm → ответ в Telegram. Добавить логирование каждого этапа, таймауты и повторные попытки на случай зависания модели.
7. Прогнать реальные голосовые суммарно на 15–20 минут, замерить время обработки и потребление RAM/CPU. При нехватке памяти — модели поменьше (whisper `base`, LLM меньше) или увеличить своп.
8. Добавить Postgres (история транскриптов/саммари) и Redis (очередь/кэш), когда понадобится.

## Файлы проекта (ожидаемые в этой папке)
- `01-setup-server.sh` — скрипт первичной настройки сервера. **Перед запуском обязательно вставить свой публичный SSH-ключ** в переменную `SSH_PUBLIC_KEY` — иначе скрипт остановится с ошибкой.
- `docker-compose.yml` — сервисы `whisper` + `ollama`, сервис `bot` закомментирован до шага 3.
- `.env.example` — шаблон переменных окружения. Переименовать в `.env`, заполнить `TELEGRAM_BOT_TOKEN` (получить у @BotFather).
- `README.md` — пошаговая инструкция по запуску шагов 1–2.

Если каких-то из этих файлов нет в папке — попросите Claude Code восстановить их по этому описанию (составы сервисов и параметры указаны выше).
