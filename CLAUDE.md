# Voice Bot — контекст проекта

## Что это
Личный Telegram-бот на Go: принимает голосовые сообщения, распознаёт речь через облачный API, делает структурированное саммари через облачную LLM.

## История решения (важно для контекста)
**перейти на облачные API**: **Yandex SpeechKit** для распознавания речи и **YandexGPT** для саммаризации. Причины выбора именно Яндекса:
- Оплата напрямую рублями (карта/СБП) без посредников и иностранных карт.
- Цена при объёме пользователя (~20 мин/день) минимальна в любом случае — экономия не была решающим фактором.
- Явных независимых сравнений качества распознавания/саммаризации на русском между провайдерами найти не удалось — выбор сделан по совокупности удобства, а не по строгим бенчмаркам.

Изначально пользователь выбрал **синхронный** режим SpeechKit (ради мгновенного ответа), но при проверке документации выяснилось, что синхронный режим ограничен 30 секундами аудио на запрос — для голосовых сообщений Telegram (которые часто длиннее) это неприменимо без нарезки на кусочки. После этого решили **перейти на обычный асинхронный режим** — см. решения ниже.

## Нагрузка
Один пользователь, ~20 минут голосовых в день суммарно, разово в день.

## Принятые решения по архитектуре (зафиксировано пользователем)
- **Режим Yandex SpeechKit: асинхронный обычный** (не синхронный, не отложенный/deferred).
  - Причина смены с синхронного: у синхронного режима жёсткий лимит **30 секунд аудио и 1 МБ на файл** (официальная документация SpeechKit) — не подходит для голосовых сообщений Telegram, которые часто длиннее. Асинхронный режим поддерживает файлы до 4 часов, что закрывает вопрос лимитов.
  - Ожидание ответа — не мгновенное (по документации асинхронная обработка может занимать от нескольких минут; точного SLA нет), но для сценария пользователя (бот обрабатывает голосовые в фоне, не в реальном времени при живом диалоге) это не критично.
  - Цена (справочно): ~0.61 ₽/мин, то есть ~366 ₽/мес при объёме 20 мин/день.
  - Важно: результаты асинхронного распознавания хранятся на сервере Яндекса только **3 дня** — бот должен успевать забирать результат (опрашивать статус операции и не затягивать).
- **Object Storage (бакет) обязателен.** Асинхронный SpeechKit принимает аудио не напрямую в теле запроса, а **по ссылке на файл в Yandex Object Storage**. Поэтому пайплайн такой: бот скачивает OGG из Telegram → загружает в приватный бакет (S3-совместимый API, статические ключи доступа сервисного аккаунта) → передаёт в SpeechKit ссылку (для приватного бакета — pre-signed URL) → опрашивает операцию → забирает текст. После обработки файл из бакета удаляется (плюс lifecycle-правило на автоудаление как страховка).
- **Версия YandexGPT: Pro.** Дороже Lite (~290 ₽/мес против ~48 ₽/мес при текущем объёме), но выбрана ради более высокого качества саммаризации. Разница в деньгах при таком объёме несущественна.
- **Деплой бота: через Docker.** Даже без тяжёлых локальных моделей (Whisper/Ollama больше не нужны) — для единообразия с будущими Postgres/Redis и простоты переноса между окружениями.
- **Сервер: конфигурация.** Текущий тариф Timeweb Cloud MSK 50 (4 CPU / 8 ГБ RAM / 80 ГБ NVMe)

## Стек
- **Backend:** Go 1.25, Telegram-бот через long polling на библиотеке **`github.com/go-telegram/bot`** (выбрана вместо `go-telegram-bot-api`: поддерживается, контексты и хендлеры из коробки) — без вебхука, чтобы не нужен был домен/SSL на старте.
- **STT (речь → текст):** **Yandex SpeechKit**, асинхронный обычный режим (модель `general`, не `deferred-general`), REST API.
  - Формат голосовых Telegram — OGG/Opus. **Проверено по документации:** OggOpus поддерживается во всех версиях API распознавания SpeechKit без ограничений — конвертация не требуется.
  - Цена: ~0.61 ₽/мин (~366 ₽/мес при 20 мин/день).
  - Результаты хранятся на сервере Яндекса только 3 дня — бот должен опрашивать статус операции и забирать результат вовремя.
- **Хранилище аудио:** **Yandex Object Storage** (S3-совместимое), приватный бакет — промежуточное хранилище для файлов, которые SpeechKit забирает по ссылке. Для доступа из Go — `github.com/minio/minio-go/v7` (endpoint `https://storage.yandexcloud.net`, статические ключи доступа; он же выдаёт pre-signed URL).
- **Саммаризация:** **YandexGPT Pro**, REST API. Требуется задать system-prompt со структурой саммари — **структура саммари пока сознательно отложена пользователем**, вернуться к этому вопросу позже, перед шагом реализации саммаризации.
- **Postgres и Redis:** НЕ используются на старте. Добавятся позже — Postgres для истории транскриптов/саммари, Redis как очередь задач или кэш.

## Как работает код сейчас
Структура:
- `cmd/bot/main.go` — точка входа: грузит конфиг, создаёт клиенты Object Storage и SpeechKit, регистрирует хендлер, запускает long polling; корректно завершается по SIGINT/SIGTERM.
- `internal/config` — читает env: `TELEGRAM_BOT_TOKEN`, `ALLOWED_USER_ID`, `DATA_DIR` (по умолчанию `data`), `YC_API_KEY`, `YC_FOLDER_ID`, `YC_BUCKET`, `YC_S3_ACCESS_KEY_ID`, `YC_S3_SECRET_ACCESS_KEY` (обязательные), `YC_S3_ENDPOINT`, `YC_S3_REGION`, `YC_GPT_MODEL` (по умолчанию `yandexgpt/latest` = Pro; есть значения по умолчанию). Прокси настраивается обычным `NO_PROXY`/`HTTPS_PROXY` в `.env` (его читают `make run` и docker compose).
- `internal/handler` — хендлер voice-сообщений.
- `internal/stt/storage.go` — загрузка в бакет, pre-signed URL (на 1 час), удаление.
- `internal/stt/speechkit.go` — клиент SpeechKit API v2: `Submit` → `Wait` (опрос раз в 5 с) → текст; `Recognize` = оба шага.
- `internal/summary/prompt.go` — system-prompt со структурой саммари; `internal/summary/yandexgpt.go` — клиент `foundationModels/v1/completion` (temperature 0.3, заголовок `x-data-logging-enabled: false`, в запрос добавляется дата отправки голосового по МСК).
- `Makefile` — `make run` (локально с `.env`), `build`, `vet`, `test`, `docker-up/down/logs`.

Структура саммари (зафиксирована пользователем, plain text без markdown, отсутствующее — «не упоминалось», «нет» только если сказано прямо): Дата (о которой речь, иначе «неизвестно»; «вчера/сегодня» пересчитываются от даты отправки) → Дневниковая запись от первого лица → Настроение → Питание → Стул → Сон → Физическое состояние → Работа → Катя → Основные занятия (успел/не успел) → Привычки (вода и жидкости, сладкое, алкоголь, курение, «гонение лысого», «занятие любовью», китайский чай; мягкие названия нужны из-за фильтра YandexGPT) → Мысли на подумать → Мысли для психолога.

Поток обработки одного голосового:
1. Приходит voice-сообщение. Если отправитель не `ALLOWED_USER_ID` — молча игнорируется (пишется warn в лог).
2. Бот скачивает OGG через `getFile` (таймаут 60 с) в `DATA_DIR/<unix>_<msgID>.ogg` и отвечает «Голосовое получено, распознаю…».
3. Файл загружается в бакет под ключом `voice/<имя файла>`, строится pre-signed URL.
4. URL уходит в SpeechKit (`general`, `ru-RU`, `OGG_OPUS`), бот опрашивает операцию. Сетевые сбои и 5xx при опросе не прерывают ожидание; общий лимит на загрузку+распознавание — 30 минут.
5. Объект в бакете удаляется (defer, отдельный контекст — сработает и при ошибке/таймауте).
6. Расшифровка уходит в YandexGPT (таймаут 3 мин), в чат приходит **только саммари** (режется на части по 4000 символов). Если саммаризация упала — бот присылает сырую расшифровку. При остальных ошибках пользователю приходит общее сообщение, детали — в логе (текст записей в лог не пишется).

Известные ограничения текущей версии:
- Локальные `.ogg` в `DATA_DIR` не удаляются (растут со временем).
- Обработка синхронна внутри хендлера, очереди и повторных попыток нет; при перезапуске бота идущее распознавание теряется.
- Длинный текст (>4096 символов) не режется на части — Telegram отклонит такое сообщение.
- Фильтр YandexGPT может блокировать откровенные темы; явную блокировку бот ловит (отдаёт расшифровку), вежливый отказ текстом придёт как «саммари».
- Go-клиент использует `HTTPS_PROXY` из окружения; если в нём локальный прокси, запросы к `*.api.cloud.yandex.net` могут зависать (см. «Сеть» ниже) — задаётся `NO_PROXY=.api.cloud.yandex.net` в `.env`.

## Результаты проверки подключения к Yandex Cloud (30.09.2026)
- Проверено руками через curl: Telegram `getMe`, YandexGPT, чтение/запись/удаление в бакете, полный цикл SpeechKit v2 — всё работает.
- **SpeechKit API v2:** `POST https://transcribe.api.cloud.yandex.net/speech/stt/v2/longRunningRecognize` с `config.specification {languageCode: ru-RU, model: general, audioEncoding: OGG_OPUS}` и `audio.uri` = **pre-signed ссылка** на объект в приватном бакете (работает). Результат: `GET https://operation.api.cloud.yandex.net/operations/{id}` до `done: true`, текст в `response.chunks[].alternatives[0].text`. Авторизация: `Authorization: Api-Key ...`.
- **Грабли с 403:** `object storage returns error, code: 403` приходил, пока API-ключ был выпущен у сервисного аккаунта без нужных прав на бакет. API-ключ и статические ключи должны принадлежать сервисному аккаунту с ролями `ai.speechkit-stt.user`, `ai.languageModels.user`, `storage.uploader`, `storage.viewer` (проверять, что ключи выпущены у одного и того же аккаунта). `YC_FOLDER_ID` должен совпадать с каталогом этого аккаунта (иначе YandexGPT отвечает 400 про несовпадение каталога).
- **Сеть:** в окружении разработки стоит локальный HTTP-прокси (`HTTPS_PROXY=127.0.0.1:2080`), через него `*.api.cloud.yandex.net` зависает — для проверок использовать `curl --noproxy '*' -4`. `storage.yandexcloud.net` и Telegram через прокси работают.
- В бакете мог остаться тестовый объект `test/voice.ogg` — удалить.
- Go в окружении разработки установлен в `/usr/local/go/bin` (добавлять в `PATH`).
